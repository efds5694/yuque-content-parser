# 语雀 AI 编辑器

一个仅在本机运行的 Edge 扩展：读取当前语雀网页编辑器中的段落，交给 WSL 中已登录的 Codex 审阅，在侧边栏展示修改差异，并在用户确认后把修改写回原文档。

它不会使用语雀 API Token，不会读取或传输浏览器 Cookie，也不会通过导入 `.lake` 创建新文档。

## 当前能力

- 支持“当前选区”和“整篇文档”两种审阅范围。
- 可修改普通段落、标题、列表项和引用中的纯文字。
- 可在顶层普通段落后创建段落，或删除顶层普通段落。
- 表格、代码、链接、折叠区、卡片以及含不受支持结构的段落保持只读。
- AI 建议必须逐项确认；事实内容变化会单独标记。
- 写入前检查完整文档指纹，写入后检查目标与相邻段落；发生异常时尝试撤销本批次输入。

> 第一版通过网页编辑器和浏览器可信输入工作。语雀更新编辑器 DOM 后，可能需要同步更新段落识别规则。请先在副本文档中完成首次验收。

## 安装

### 1. 启动本地服务

在 Windows 资源管理器中打开本项目目录，双击 [start.cmd](./start.cmd)。

项目位于 WSL 时，可在资源管理器地址栏输入：

```text
\\wsl.localhost\Ubuntu\home\administer\语雀AI编辑器
```

启动窗口会显示本地服务地址和一个 48 位配对码。窗口必须保持开启。配对码首次生成后保存在 Windows 当前用户的：

```text
%LOCALAPPDATA%\YuqueAIEditor\bridge-token
```

桥接层依次查找：

1. `YUQUE_AI_CODEX_BIN` 指定的 Codex；
2. WSL `PATH` 中的 `codex`；
3. VS Code/Codex 扩展目录中的 Codex 可执行文件。

当前环境中的 Codex 位于 VS Code Server 扩展目录，脚本会自动发现它。`codex exec` 以 `--ephemeral --sandbox read-only --output-schema` 运行，并复用 WSL 中现有的 CLI 登录状态。

### 2. 在 Edge 中侧载扩展

1. 打开 `edge://extensions/`。
2. 开启“开发人员模式”。
3. 点击“加载解压缩的扩展”。
4. 选择本项目的 `extension` 文件夹。
5. 可选：将“语雀 AI 编辑器”固定到工具栏。

扩展申请 `debugger` 权限是为了通过 Chrome DevTools Protocol 发送可信键盘输入。它不会执行网络调试或读取 Cookie。使用时如果该语雀标签页已经打开开发者工具，Edge 不允许扩展同时连接；请先关闭 DevTools。

### 3. 首次配对

1. 在 Edge 打开需要修改的语雀文档并进入编辑模式。
2. 点击扩展图标，打开侧边栏。
3. 展开“本地服务设置”，粘贴 `start.cmd` 窗口显示的配对码。
4. 点击“连接”。

配对码只保存在本机扩展的 `chrome.storage.local` 中。本地服务仅监听 `127.0.0.1`，只接受扩展来源，并使用恒定时间比较配对码。

## 使用

1. 对局部修改，先在语雀正文中选中文字，再选择“当前选区”；也可以选择“整篇文档”。
2. 输入修改要求，点击“读取文档并生成建议”。
3. 检查每项原文、新文、理由和“事实变化”标签，取消不希望应用的项目。
4. 点击“应用已选修改”。
5. 等待语雀显示“已保存”，刷新页面确认结果。

建议第一次在用户提供的副本文档中分别测试：

- 一处普通文字替换；
- 一处加粗文字附近的替换；
- 创建和删除一个普通段落；
- 包含表格、流程图和代码块的整篇审阅；
- 生成建议后先手工改动原文，确认工具会拒绝过期建议。

## 安全边界

- 正文会作为请求内容发送给当前 WSL Codex 会话，但不会写入桥接服务日志。
- 扩展不申请 `cookies` 权限，不调用语雀私有保存接口，也不设置整篇 `innerHTML`/Lake 文档。
- 写回只发生在用户点击确认后。目标块 ID、原文字、页面 URL 和整篇内容指纹任一不匹配都会停止。
- 每个修改使用字符级差异，从段落末尾向前应用，以保留未改动文字上的行内格式。
- `.lake` 文件仅作为测试夹具和人工备份；工具不会自动导入它。

## 限制

- 含链接、代码、卡片、换行节点或未知行内结构的整个段落会标为只读。
- 单项修改只能处理一个段落，不能在新文字中包含换行。
- 创建和删除仅限顶层普通段落；标题、列表项和引用只允许替换文字。
- Edge 的 `debugger` 输入通道无法与同一标签页的 DevTools 同时使用。
- 自动撤销依赖语雀编辑器的原生历史记录；若页面在写入中刷新或崩溃，必须人工检查文档并使用 `Ctrl+Z`。

## 故障排查

### 本地服务找不到 Codex

先在 WSL 中运行：

```bash
codex --version
```

若 Codex 位于自定义位置，在启动 `start.cmd` 前设置 Windows 环境变量：

```bat
set YUQUE_AI_CODEX_BIN=/home/你的用户名/路径/codex
```

如果 WSL 发行版或项目路径无法自动识别，可设置：

```bat
set YUQUE_AI_WSL_DISTRO=Ubuntu
set YUQUE_AI_WSL_USER=你的WSL用户名
set YUQUE_AI_WSL_PROJECT=/home/你的WSL用户名/语雀AI编辑器
```

### 侧边栏显示“请进入编辑”

- 确认当前标签页地址以 `https://www.yuque.com/` 开头。
- 确认已经点击语雀的“编辑”按钮，正文中出现可输入光标。
- 安装或重新加载扩展后，刷新一次语雀页面。

### 只识别到少量块或显示“0 个可编辑”

从 `0.1.1` 起扩展会自动发现语雀正文所在的 iframe；从 `0.1.2` 起支持新版编辑器的自定义元素；从 `0.1.3` 起兼容当前语雀的 `.ne-b-filler` 段尾占位符，以及 `ne-tli` 列表和标题的独立正文容器。请在 `edge://extensions/` 点击扩展卡片上的“重新加载”，随后刷新语雀页面。若仍失败，侧边栏错误会列出“编辑器根节点、Lake ID、候选段落、稳定 ID”四个诊断值，请一并反馈。

### 无法连接浏览器输入通道

关闭当前语雀标签页的开发者工具，再点击应用。Edge 会在扩展连接期间显示调试提示，这是 `chrome.debugger` 的正常行为。

### 没有识别到“已保存”

这不代表一定保存失败。观察语雀页面右上方保存状态，稍等后刷新检查；若内容没有持久化，使用语雀原生撤销恢复。

## 开发与测试

项目不依赖第三方 npm 包，需要 Node.js 20 或更高版本：

```bash
npm test
npm run check
```

测试覆盖结构化协议、只读块拒绝、Unicode 字符差异、本地服务鉴权以及样例 `.lake` 中的表格、卡片、流程图、代码块和 ID 唯一性。受限沙箱中运行桥接 HTTP 测试时，需要允许临时监听 `127.0.0.1` 随机端口。

主要目录：

```text
extension/  Edge MV3 扩展、侧边栏和页面适配器
bridge/     Windows 本地服务、Codex 启动器和 JSON Schema
test/       Node 内置测试
```

## Codex 调用依据

桥接实现遵循 [OpenAI 官方 Codex 非交互模式文档](https://learn.chatgpt.com/docs/non-interactive-mode)：`codex exec` 支持从脚本运行、只读沙箱、临时会话、复用 CLI 登录和 `--output-schema` 结构化结果。
